# RULES

Standing law for every session in this repository. `GOAL.md` is the finish line. `AGENTS.md` is how to work on the Iris Windows machine. `BOTS.md` seats roles. `CODE_REVIEW_CHECKLIST.md` is the review. This file wins on process.

1. Never open a pull request. Do not create one, do not ask for one, and do not let tooling open one. Land work as commits on `runner-h` and push that branch to `origin` when this clone already has that remote. Iris commits only: the commit is made on this Iris checkout. A review note from another machine is not a commit from here.
2. Only create new commits. Never amend, rebase, squash, reset, or otherwise rewrite history. Never force-push. Never set `starting_ref`. The only reset this file allows is the local Nvidia Ask teardown in rule 12.
3. Cable proofs are Windows-local. Capture is WASAPI by friendly name. Use VB-Audio (a BB cable): play into the cable input, capture from the cable output. Leave the room microphone out of cable proofs. During a chain proof and a Mouth one-shot, playback is `PlaySoundW` on the default waveform device, set to `Speakers (Realtek(R) Audio)` on this worker, so capture does not hear the mouth. `mouth.py` has no device flag. `hear.py` is the PC-mic one-shot (Intel Smart Sound on this worker). Cable proofs stay on the cable.
4. An extended commit message carries only the delta for this change: what changed, why, and the method used for this step. Point to `GOAL.md`, `AGENTS.md`, `RULES.md`, and `BOTS.md` for the standing handoff. Do not copy those files into the message. Do not dump chat history, an earlier assignment, or another computer's notes into the commit.
5. One role, one executable, one text file. Files are the only meeting place. Do not add an orchestrator. One-shot contracts are in `GOAL.md`. Role routing is in `BOTS.md`. Qwen3-0.6B has no vision; `qwen.py` is text only and `--image` exits 2. Do not commit `gemma_run.txt`, `sense_run.txt`, `mouth.txt`, generated audio, run outputs, models, the install tree, or the virtual environment.
6. `chatterbox.exe` is the synthesizer. `chatterbox.play` is `on` or `off`. `off` writes the wav and skips PlaySound so `mouth.py` can overlap playback with the next synthesize. Direct `chatterbox.exe` with `on` plays itself. Do not add a second synthesizer in Python.
7. When behavior changes, rewrite `GOAL.md`, `AGENTS.md`, `RULES.md`, `CODE_REVIEW_CHECKLIST.md`, and `BOTS.md` from zero so they match the tree. Keep them atemporal: current rules and contracts, no incident log, no commit hash as law.
8. Prefer one commit for one change. A second commit is only to repair a broken commit that was just created for that same change, and it is a new commit, not an amend.
9. Prove with the real executables on this machine. One program, then the cable chain. Run a failed proof once more. If it fails again, leave the system able to start, record what happened and what will change, and change approach. Do not add a harness, a mock, or a script that pretends a program ran.
10. Do not change C++ / `.cpp` without Wojciech's explicit go. The PlaySound C++ delta is PARKED until the next war room decides. Python and markdown docs cook without that go when SPOC routes them.
11. Trident Ask is V2. On Iris, run `qwen.py` in the worker shell. Do not launch a Cloud Agent or a Cursor coding agent for that ask. On Nvidia, one Cloud Agent only: model `composer-2.5`, `fast` false, prompt equal to the exact command. The return is the exit code, stdout, and a short stderr summary (at most 20 non-tensor lines, or a byte count plus the first and last 5 lines). Do not paste a gemma or qwen loader log. Image asks are `gemma.py --image` on Nvidia. `qwen.py --image` exits 2. Ask does not edit the repo.
12. Mandatory Nvidia Ask teardown, after every Nvidia ASK GO Cloud Agent run, success or fail, before FINAL. Trident Ask V2 runs it on the trident-nvidia Trident cwd. `git fetch origin runner-h`, then `git status -sb` and `git status --porcelain`. If HEAD is not `origin/runner-h` or porcelain is non-empty: `git checkout runner-h`, then `git reset --hard origin/runner-h`. That reset is local only. Never force-push. Do not keep agent churn. Re-check that porcelain is empty and HEAD matches `origin/runner-h`. FINAL includes the tip SHA, the exit code, stdout, the short stderr summary, and nvidia git clean yes/no (before, then after, when a reset ran). A Cursor UI line such as `Changes +N/−M across N files` is not proof of a good ask and does not replace git status. `git status --porcelain` is the source of truth. Ask does not commit, push, open a pull request, create a recovery agent, or fix the tree. Teardown is reset to origin, not a second cook. If Ask cannot run git on that worker, FINAL is BLOCKER dirty-unknown so Executor can COOK the same reset. Prefer Ask running the hard reset on the same worker shell when the Cloud Agent path cannot.
