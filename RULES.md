# RULES

Standing law for every session in this repository. `GOAL.md` is the finish line. `AGENTS.md` is how to work on this Windows machine. `BOTS.md` is how to seat the same roles with no chat history. `CODE_REVIEW_CHECKLIST.md` is the Pass/Fail/Blocked review. This file wins on process.

1. Never open a pull request. Do not create one, do not ask for one, and do not let tooling open one. Land work as commits on `runner-h` and push that branch to `origin` when this clone already has that remote. Iris commits only: the commit is made on this Iris checkout. A review note from another machine is not a commit from here.
2. Only create new commits. Never amend, rebase, squash, reset, or otherwise rewrite history. Never force-push.
3. Cable proofs are Windows-local. Capture is WASAPI, chosen by friendly name, not by device index. Use a virtual audio cable (VB-Audio; the person may call it a BB cable): play into the cable input, capture from the cable output. Leave the room microphone out of cable proofs. If no cable is installed, install one. During a chain proof the mouth plays on the real speakers, not into the cable input, so capture does not hear the mouth. A Mouth one-shot uses those same default speakers. `mouth.py` has no device flag. `hear.py` is the separate PC-mic one-shot: record, then one `nemo-speech.exe transcribe`, transcript on stdout. It does not replace the cable proof.
4. An extended commit message carries only the delta for this change: what changed, why, and the method used for this step. Point to `GOAL.md`, `AGENTS.md`, `RULES.md`, and `BOTS.md` for the standing handoff. Do not copy those files into the message. Do not dump chat history, an earlier assignment, or another computer's notes into the commit.
5. One role, one executable, one text file. Files are the only meeting place. Do not add an orchestrator. The mouth's Lego contract is a settings file passed to `chatterbox.exe`. `mouth.py` is the speak entry for a Mouth one-shot: `--model` is `nano`, `turbo`, or `v3` (default `nano`); omitted `--lang` is `en` for `nano` and `turbo`, and `pl` for `v3`. One invocation may take several TEXT arguments, and that is one process. A separate process per chunk is a reported fallback, not a silent one. Validate every chunk first. Each chunk is a cold `chatterbox.exe` synthesize with `chatterbox.play off`, while `mouth.py` plays wavs on the speakers and overlaps the next synthesize. It does not synthesize in Python. `hear.py` stays the hearing one-shot and stays in the repository beside `mouth.py`. Do not commit generated audio, `mouth.txt`, run outputs, models, the install tree, or the virtual environment. Role seating, SPEAK GO, HEAR GO, and cook routing are in `BOTS.md`.
6. `chatterbox.exe` remains the synthesizer. `chatterbox.play` is `on` or `off`. `off` writes the wav and skips PlaySound so `mouth.py` can overlap playback with the next synthesize. Direct `chatterbox.exe` with `on` still plays itself. Do not add a second synthesizer in Python.
7. When behavior changes, rewrite `GOAL.md`, `AGENTS.md`, `RULES.md`, `CODE_REVIEW_CHECKLIST.md`, and `BOTS.md` from zero so they match the tree. Keep them atemporal: current rules and contracts, no incident log, no commit hash as law.
8. Prefer one commit for one change. A second commit is only to repair a broken commit that was just created for that same change, and it is a new commit, not an amend.
9. Prove with the real executables on this machine. One program, then the cable chain. Run a failed proof once more. If it fails again, leave the system able to start, record what happened and what will change, and change approach. Do not add a harness, a mock, or a script that pretends a program ran.
