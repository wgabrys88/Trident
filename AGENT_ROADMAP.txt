Target machine: Windows x64, Intel host (AVX2), NVIDIA GTX 1060 6GB (Pascal sm_61).
Philosophy: bare-metal inference, one GPU backend per workload, no fallbacks, no
defensive coding, no duplicate paths, no legacy wrappers. Delete dead code; do not
comment it out. Hard work over shortcuts.

--------------------------------------------------------------------------------
WHY TWO GPU STACKS (not one API for everything)
--------------------------------------------------------------------------------
[BRAIN / GEMMA]  CUDA only (ggml-cuda), sm_61-real, CUDA toolkit <= 12.6.
  - Pascal consumer GPUs: FP16/BF16 matmul is slow; use Q4_0 (or similar) + MMQ.
  - Flash Attention tile path on Pascal (GGML_CUDA_FA); full GPU offload n_gpu_layers=999.
  - GGML_CPU=ON is required for llama.cpp buffer registration; inference still on GPU.
  - Binary: gemma/build/Release/gemma-brain.exe (NOT python llama for production brain).

[TTS / CHATTERBOX]  Vulkan only (ggml-vulkan), same physical GTX 1060.
  - TTS graphs are smaller; Vulkan on Pascal is fine; shares VRAM with CUDA brain.
  - Do NOT port Chatterbox to CUDA until brain+TTS VRAM scheduling is designed.
  - Binary: build/bin/chatterbox.exe (replaces deleted chatterbox-server + named pipe).

[ASR / EAR]  Next bare-metal target (not done in this commit).
  - Today: python ear.py + Nemotron streaming (models/ear/).
  - Goal: C++ Vulkan or CUDA ASR executable, same style as chatterbox.exe, no pipe.

VRAM rule: 6GB cannot hold full multimodal Gemma + long TTS + ASR simultaneously.
Serialize heavy jobs or shrink n_ctx / clip TTS text per call.
